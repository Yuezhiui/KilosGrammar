## Source runner: what is reusable

- Upstream [`project.godot`](https://github.com/mujtaba-io/3d-endless-runner/blob/main/project.godot) declares Godot **4.2**, `gl_compatibility`, and `res://Levels/Level.tscn`; local Kilos Grammar targets **4.7 / Forward Plus**. The project is a relevant **Godot 4** reference, but its project settings, input map, scenes, and runtime should not be wholesale merged.
- [`Levels/Level.gd`](https://github.com/mujtaba-io/3d-endless-runner/blob/main/Levels/Level.gd) spawns a road, coins, rocks, and environment objects in three fixed X lanes (`[-2, 0, 2]`). [`Levels/MovingObject.gd`](https://github.com/mujtaba-io/3d-endless-runner/blob/main/Levels/MovingObject.gd) translates objects along world Z and frees them on a 5-second timer. Reuse **the concept of scrolling/recycled scenery and lane-relative positions**; drive approach distance using Human Plane's existing speed/progress instead of the reference's `global_translate(Vector3(0, 0, 0.25))` per frame (frame-rate-dependent).
- [`Player/Player.gd`](https://github.com/mujtaba-io/3d-endless-runner/blob/main/Player/Player.gd) uses a `CharacterBody3D`, keyboard `ui_left/ui_right`, jumping/gravity, and coin collision. That movement model conflicts with camera/body-controlled flight; adapt its idea of smoothly mapping among three X lanes, not its character controller, physics, or input handling. It also calls `lerp(..., MOVE_SPEED * delta)` without explicit weight clamping; avoid extrapolation under a frame hitch.
- Upstream [`LICENSE`](https://github.com/mujtaba-io/3d-endless-runner/blob/main/LICENSE) is **MIT, Copyright (c) 2024 Mujtaba**. Preserve its copyright and permission notice when copying substantial upstream code or assets.

## Recommended Godot 4.7 integration

1. Store every runtime asset inside `res://Components/Gameplay/Human Plane/3D/` (for example, `.../NATURE/toy_plane/scene.gltf` with `scene.bin` and its `textures/` directory intact). Godot recommends **glTF 2.0**; Godot 4.3+ also imports FBX with the built-in **ufbx** importer. Review the five FBX and skybox material orientations in Advanced Import Settings, and convert to `.glb` only when import or material tests show an actual problem. See [Godot available 3D formats](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html).
2. The existing [`ui/minigames/human_plane.tscn`](../../ui/minigames/human_plane.tscn) root is `Control`; its `HUDLayer/HUD` is a `CanvasLayer` at layer 20. A `SubViewportContainer` / `SubViewport` hosting `Node3D`, camera, lights, aircraft and scenery can display true 3D beneath the **existing editable 2D HUD**. Keep the top-level `requested(target, payload)` signal and `set_context`, `get_context`, `_pause`, `_resume`, and `_finish_round` interfaces used by `ui/play/gameplay.gd` / `main_menu.gd`. See [SubViewport](https://docs.godotengine.org/en/stable/classes/class_subviewport.html).
3. Keep the camera bridge: `ui/play/gameplay.gd` supplies `set_airplane_pose_active(eligible)` only for fresh, calibrated **two-arms-spread** poses and `set_body_x(-1..1)` from `PoseService.normalized_body_x()`. Human Plane freezes its current X when arms drop/tracking fails and respects pause; continue mapping that normalized X to the 3D plane's editor-authored three-lane extent. Do not use the runner's keyboard/jump controls. Tracking loss also suspends the wrapper after 0.65 s.
4. Create **three torus donut rings** with native `MeshInstance3D` + `TorusMesh` (`inner_radius`, `outer_radius`, `rings`, `ring_segments`). A torus normally lies in the horizontal XZ plane; rotate the ring about its local X axis **90°** to face a camera looking along the track's Z axis. Place a `Label3D` slightly in front of the ring hole, set `billboard` to face the camera and use the existing Titan One font, outline, sufficient world size, and legible color. Preserve the actual options from `round_data.options` (e.g., `APPLE`, `RUN`) and the topic prompt (e.g., `FIND THE NOUN`) from the current grammar bank; if displaying `NOUN`/`VERB`/`ADJECTIVE` category labels additionally, do not replace question data with fixed hardcoded strings. [TorusMesh](https://docs.godotengine.org/en/stable/classes/class_torusmesh.html) · [Label3D](https://docs.godotengine.org/en/stable/classes/class_label3d.html).
5. Preserve the existing **60-second Seconds mode, 3-life Lives mode, 100 points/correct, three-lane wave choices, per-difficulty gate speed, prefetch/no-teleport behavior, and answer-line crossing resolution** in `ui/minigames/human_plane.gd`. Animate ring groups along track Z based on the existing normalized `gate_progress` and `next_gate_progress`; resolve a selected lane **once when the active ring group reaches the player/crossing plane**, with existing hit/miss penalties and pause/resume semantics. Use editor-authored markers for lane centers, collision width, near/far Z, camera and ring sizes; avoid rendering-based collision differences.
6. Keep scenery lightweight for webcam + pose inference: instance/recycle a limited number of trees, rocks and road chunks, cap visibility distance, use simple lighting and test GPU cost at 1280×720, 1600×900 and 1920×1080. Check that the 6K JPG is appropriate as a panorama before assigning it to `PanoramaSkyMaterial`; downsize only if necessary after profiling.

## Validation required during implementation

- Godot 4.7.2 editor import and parsing: FBX, glTF, all texture references and `PackedScene` loading; inspect model scale, front-facing aircraft, sky orientation, alpha/PBR and material quality.
- Live GUI screenshots at 1280×720 / 1600×900 / 1920×1080: check three ring holes and text readability, camera distance, player-to-ring overlap, unmodified HUD alignment and editor-friendly adjustments.
- Regressions with mocked pose input (no live database): move left/center/right, arms down freeze, camera lost pause, resume, ring-crossing correct/incorrect/missed, difficulty speeds, 60 s timeout, lives exhausted, prefetched next wave, pause/menu/results routing. Measure render FPS alongside pose capture, rather than assuming 60 FPS from a static render.

**Audit limit:** source inventory and code/API behavior were inspected; no assets were copied/imported, no scene run or runtime FPS was measured, and no ownership rights for unlicensed scenery were inferred.
