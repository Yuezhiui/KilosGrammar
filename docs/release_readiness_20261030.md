### Remaining findings and triage

1. **Catch visible bounds — needs owner/art acceptance (open).** `test_catch_alpha_framing.gd` fails **138/955** checks across 45 character/map/resolution cases. Some failures are stale assumptions: its asserted layering is Body 0 / Basket 1 / Fruit 2, whereas current deliberate composition is Body 0 / Fruit 1 / Basket 2, with no text labels on collected fruit. However, measured opaque basket rectangles do extend just below the viewport: e.g., Cat at 1280x720 has top `y=599.045`, height `121.538` (bottom `720.583`), and Panda at 1920x1080 has bottom around `1081.71`. This is roughly **0.6–1.7 px** overflow; verify the intended artist crop and decide whether to adjust or explicitly accept it. The other failing fixtures are `test_catch_character_editor_rig` (**105/1,786** failures), `test_catch_character_alignment` (**105** failures), and `test_catch_new_character_alignment` (**219** failures). Many assert retired `APPLE HALF` art, collected-word labels, or all body pixels fitting inside the viewport. Do not silently mark these PASS or change Catch geometry solely to satisfy obsolete expectations.
2. **Human Plane incoming-gate preview brightness — behavior/spec review required.** `test_human_plane_continuous_integration.gd`: **21/462** failures, all associated with the preloaded upcoming trio being *dim*. Current `human_plane.gd:_render_gate_trio` sets `gate.modulate.a=1.0` for unresolved gates, including prefetched ones. The tests still confirm other wave and handoff invariants, but the observed preview-opacity difference may be visible gameplay clutter. Inspect a native naturally timed three-gate handoff before deciding whether a dim preview is still required.
3. **Human Plane stale integration/visual assertions — reconcile, then rerun.** `test_human_plane_body_integration` fails **3/9** on completing the old neutral hold using eight frames over 2.5 seconds; current calibration requires **3 seconds** and authenticated observations. `test_human_plane_three_heart_hud` fails **156/1,195** and emits a script property-access error because it demands exact geometry/art parity with an older Catch editor layout, while current Human Plane retains its separate editor-authored HUD and a `ScoreBottomContainer`. `test_human_plane_solid_gate_handoff_20261029` fails **9/225**, partly because it requires a removed `FlightBackground` node, while the current scene uses other authored background/3D layers; it also assumes prefetched gates remain hidden even though current code explicitly shows the upcoming trio. These failures are real test failures, but **not proof that gameplay itself is broken**.
4. **Leaderboard Oct 24 visual fixture is outdated.** `test_leaderboard_oct24_visual.gd`: **6/418** failures, exactly two per viewport, requiring old `BACKGROUND.png` and `BACK.png`. The current leaderboard scene deliberately uses `Components/Credits/Redesign/background1.png` and the Credits `HOME.png` artwork. Current leaderboard design, native filter-pointer behavior, and no-socket database ranking/invalidation integration all pass; update the older fixture to the approved artwork before a clean suite claim.
5. **Balloon native QA score and pause checks PASS with current artwork.** The 2026-10-30 OpenGL rerun succeeded after the QA fixture accepted the artist's approximately 3-pixel vertical inset for `BannerTagline` inside the cream strip (instead of demanding pixel-identical Catch coordinates). It still checks that the label is inside the correct strip rather than the headline, source title ratio is preserved (`1959x477`), score `250` stays clear of title/timer/lives/pause, timer and 2-heart artwork are correct, pause glyph and hitbox are aligned, and screenshots match actual pixels.

## Packaging and target-PC acceptance blockers

- **Source version is now aligned:** local `VERSION` and `origin/main:VERSION` both read `0.3.0-beta.1`; current `export_presets.cfg` file and product metadata both read `0.3.0.0`. The older `docs/DEPLOYMENT.md` statement claiming local 0.2.0 and export 0.1.0 is stale and should be updated by its document owner. A complete published binary release/version-tag was **not verified** by these QA tests.
- **Missing release bytes (verified):** `release/windows/offline/manifest.json`, `release/windows/out/KilosGrammar-win-x64/KilosGrammar.exe`, `KilosGrammar.pck` and package `manifest.json` do **not exist** in this checkout. An installed launcher, offline YOLO weights/wheelhouse, validated export templates, checksums and redistribution rights must be supplied before asserting a complete offline package. See `release/windows/README.md` and `docs/DEPLOYMENT.md`.
- **No disconnected-school-PC acceptance:** the suite does not test a fresh Windows x64 installation, Python 3.11/wheelhouse and PostgreSQL service startup, offline pose worker/model behavior, webcam permissions, live multi-person isolation, real graded student completion, leaderboard retention after app restart, or graceful shutdown with real GPU/DB resources. No actual PostgreSQL service or student records were touched.

**Release recommendation:** Source beta may be reviewed as a development build, but the **offline installer/EXE release and deployment signoff must stay blocked** until package preflight, physical installation and full offline classroom walkthrough succeed. Separately decide the Catch 1–2 px opaque basket clipping and Human Plane prefetch brightness, and update legacy test fixtures to the current accepted artwork/layout without masking live regressions.
